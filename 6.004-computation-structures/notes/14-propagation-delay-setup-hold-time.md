# Propagation Delay, Setup/Hold Time

## Why this matters

Every proof in Topics 03–13 quietly assumed gates and flip-flops respond *instantly* — Topic 06 flagged this explicitly ("propagation delay... deferred to Topic 22" — since renumbered, this note), and Topic 13's entire correctness proof (Section 2) relied on treating a combinational circuit as producing a constant output the instant its inputs are constant, with no transition time modeled at all. That idealization was the right choice for proving *logical* correctness (what value eventually gets computed/captured) without getting bogged down in electrical detail — but real gates take nonzero time to respond to an input change, and a real flip-flop needs its $D$ input to be stable for a real window of time around the clock edge, not just "at" a mathematical instant. This note replaces the zero-delay idealization with a precise, quantitative timing model — **propagation delay** and **contamination delay** for combinational logic, **setup time** and **hold time** for flip-flops — that Topic 15 (clock skew) and Topic 16 (maximum clock frequency) build on directly to answer the very practical question "how fast can this synchronous circuit actually run, and is it guaranteed to work at all?"

## Builds on

- [[6.004-computation-structures/notes/13-implementing-fsms-flip-flops]] — the general synchronous FSM architecture (state register + next-state logic on a shared clock) and its Section 2 correctness proof, which explicitly assumed instantaneous, delay-free combinational evaluation; this note replaces that idealization with a real timing model and shows exactly what additional constraints the real (non-ideal) circuit must satisfy for Topic 13's proof to still hold in practice.
- [[6.004-computation-structures/notes/06-adders-basic-arithmetic]] — the ripple-carry adder's carry chain, whose "delay grows with $n$" behavior was flagged informally (Core definitions, "Propagation delay of a ripple-carry chain," deferred here) but never quantified; this note supplies the actual formula and a worked numeric calculation using that same adder.
- [[6.004-computation-structures/notes/09-d-latch-transparency-problem]] — setup time and hold time were named informally there (Core definitions, "formalized in Topic 22") without a precise definition; this note supplies that formalization.

## Core definitions

- **Propagation delay of a gate ($t_{pd}$)** — the worst-case (i.e., maximum, over all input transitions and operating conditions the gate is specified for) time from a change at a gate's input to the point at which its output is *guaranteed* to have reached its final, correct new value.
- **Contamination delay of a gate ($t_{cd}$)** — the best-case (minimum) time from a change at a gate's input to the *earliest possible* point at which its output might start to change; before this much time has elapsed, the output is guaranteed to *still* be at its old value. $t_{cd} \le t_{pd}$ always (the earliest possible start of a change can never be later than the guaranteed-complete time).
- **Uncertain window** — the interval $(t_{cd}, t_{pd})$ after an input change, during which a gate's output is neither guaranteed to have finished changing nor guaranteed to have not yet started — a statement about the limits of what a worst/best-case timing model can promise, not a claim that the signal takes some third, in-between logic value during this window (echoed in Common Pitfalls, and directly analogous to — but a genuinely different axis from — 6.002 Topic 04's voltage-domain noise margins).
- **Path delay (propagation / contamination)** — for a chain of gates forming one path through a combinational circuit, the *sum* of the individual gates' $t_{pd}$ (respectively $t_{cd}$) values along that path, since each gate in the chain must wait for its input to be ready before it can begin (respectively, could begin) responding.
- **Circuit propagation / contamination delay** — for an entire combinational circuit (possibly many parallel paths from inputs to outputs), the circuit's overall $t_{pd}$ is the *maximum* path-propagation-delay over every input-to-output path (the **critical path**); the circuit's overall $t_{cd}$ is the *minimum* path-contamination-delay over every path (the **short path**, potentially a different, shorter path than the critical one).
- **Clock-to-$Q$ delay ($t_{pd,FF}$ / $t_{cd,FF}$)** — the flip-flop analogue of gate delay: $t_{pd,FF}$ is the worst-case time from a triggering clock edge to the flip-flop's $Q$ output being guaranteed to reflect the newly-captured value; $t_{cd,FF}$ is the best-case (earliest possible) time from the edge to $Q$ possibly starting to change.
- **Setup time ($t_{setup}$)** — the minimum length of time *before* a triggering clock edge during which a flip-flop's $D$ input must already be stable (settled to its final value) for that value to be reliably captured.
- **Hold time ($t_{hold}$)** — the minimum length of time *after* a triggering clock edge during which a flip-flop's $D$ input must *remain* stable (not yet start changing to some new value) for the just-triggered capture to be reliable.

## Intuition

**Propagation delay and contamination delay bound a signal's transition the same way $V_{OL}/V_{OH}$ bound its voltage — but along the time axis instead of the voltage axis.** 6.002 Topic 04's digital abstraction accepted that a real voltage is continuous and noisy, and built a discipline (guaranteed output bands, required input bands) around that fact rather than pretending voltages are perfectly clean. This note does the identical move for *time*: a real gate's output doesn't snap instantly to its new value the moment the input changes, so instead of pretending it does (as Topics 03–13 did for logical clarity), this note gives two hard guarantees — "the output has definitely finished changing by $t_{pd}$" and "the output definitely hasn't started changing before $t_{cd}$" — and treats everything in between as an honestly-acknowledged gap in what can be promised, not a value the circuit takes on.

**Setup and hold time are exactly the "how much lead time / how much settle time does a snapshot camera need" constraints, applied to a flip-flop's capture.** A camera with a slow shutter needs its subject to hold still for a moment *before* the shutter fully opens (or the exposure starts blurry) and to keep holding still for a moment *after* it starts closing (or the tail end of the exposure blurs too) — setup time is the "before" requirement, hold time is the "after" requirement, both measured relative to the clock edge that triggers the capture. Get either wrong — the data changes too late before the edge, or changes back too soon after it — and the flip-flop may capture a value that was never stable, which is exactly the physical circumstance that risks the metastability Topic 08 flagged (an infinitesimal perturbation at the wrong moment failing to resolve cleanly to either digital state).

**Setup violations and hold violations are governed by *opposite* extremes of a circuit's delay, which is why they need to be checked separately.** A setup violation happens when the *slowest* (worst-case, $t_{pd}$) path from the previous edge to this flip-flop's $D$ input takes too long, leaving less than $t_{setup}$ before the next edge — this is a "the signal arrived too late" problem, governed by the *longest* path. A hold violation happens when the *fastest* (best-case, $t_{cd}$) path lets $D$ start changing again too soon after the edge that just captured it, before $t_{hold}$ has elapsed — this is a "the signal changed again too early" problem, governed by the *shortest* path. These are opposite failure modes governed by opposite ends of the delay spectrum, which is exactly why Topic 15 and Topic 16 need to analyze worst-case and best-case paths separately rather than reasoning about "the" delay of a circuit as if it were a single number.

## Derivation / formalism

### 1. From gate delay to circuit delay: paths, critical path, short path

Given a combinational circuit built from gates each with known $t_{pd},t_{cd}$ (Topics 03–04), consider any single path from a circuit input to a circuit output, passing through gates $g_1,g_2,\dots,g_r$ in sequence. **Path propagation delay:** $t_{pd,\text{path}} = t_{pd}(g_1)+t_{pd}(g_2)+\cdots+t_{pd}(g_r)$ — because gate $g_2$ cannot begin responding until $g_1$'s output is *guaranteed* ready (worst case), and so on down the chain; summing worst-case delays along the path gives the worst-case time for a change to propagate end-to-end along that specific path. **Path contamination delay:** $t_{cd,\text{path}} = t_{cd}(g_1)+\cdots+t_{cd}(g_r)$, by the symmetric best-case argument — the earliest a change could possibly ripple all the way through is if every gate along the way responds at its own fastest possible ($t_{cd}$) rate.

For the whole circuit (potentially many such paths, from various inputs to various outputs): **circuit $t_{pd} = \max$ over all paths of that path's $t_{pd,\text{path}}$** (the overall output isn't guaranteed correct until even the *slowest* path has had time to settle — this is the **critical path**). **Circuit $t_{cd}=\min$ over all paths of that path's $t_{cd,\text{path}}$** (some output might start changing as early as the *fastest* path allows — this is the **short path**, and in general a different path through the circuit than the critical path, since a path can be "long" in gate count but built from fast gates, or vice versa).

### 2. Worked derivation: the $n$-bit ripple-carry adder's propagation and contamination delay

Using the two-half-adder-plus-OR full-adder decomposition (Topic 06, Section 3: $S_1=A\oplus B$, $C_1=AB$ from HA1; $S_2=S_1\oplus C_{in}$, $C_2=S_1\cdot C_{in}$ from HA2; $C_{out}=C_1+C_2$ from the final OR gate), trace the path from a given bit's $C_{in}$ to that same bit's $C_{out}$: $C_{in}\to$ (AND gate, computing $C_2$) $\to$ (OR gate, computing $C_{out}$) — two gates, since $S_1$ (feeding both the AND and, together with $C_{in}$, the sum) is computed from $A,B$ alone and does not depend on $C_{in}$, so it is already stable long before $C_{in}$ arrives and does not add to *this* specific path's length. So **each full-adder stage's carry-in-to-carry-out path delay** is $t_{pd,\text{stage}} = t_{pd}(\text{AND})+t_{pd}(\text{OR})$.

For an $n$-bit ripple-carry adder (Topic 06, Section 4: $C_{in}^{(0)}=0$, each stage's $C_{out}$ feeds the next stage's $C_{in}$), the path from $C_{in}^{(0)}$ to the final overflow bit $C_n$ passes through all $n$ stages' carry chains in series:
$$t_{pd,\text{adder}} \ (\text{to } C_n) = n\cdot\left(t_{pd}(\text{AND})+t_{pd}(\text{OR})\right)$$
— this is the precise, quantitative version of Topic 06's informally-flagged claim that ripple-carry delay "grows with $n$": it grows *linearly* in $n$, with a fixed per-bit cost of one AND-gate delay plus one OR-gate delay. The contamination delay to $C_n$ is the analogous sum using $t_{cd}$ instead: $t_{cd,\text{adder}}(\text{to }C_n) = n\cdot(t_{cd}(\text{AND})+t_{cd}(\text{OR}))$.

### 3. The setup-time constraint on a synchronous circuit

Consider one flip-flop in a Topic 13-style state register, whose $D$ input is driven by next-state logic reading (among possibly other things) another flip-flop's $Q$ output. For the capturing flip-flop to reliably sample the correct value at a clock edge occurring $T$ time units after the *previous* edge (i.e., clock period $T$): the driving flip-flop's $Q$ must become valid (worst case, $t_{pd,FF}$ after the previous edge), then the intervening next-state logic must finish propagating that value to $D$ (worst case, the next-state logic's circuit $t_{pd}$, Section 1), and *then* $D$ must remain stable for at least $t_{setup}$ before the *next* edge arrives. Requiring all of this to fit within one clock period:
$$T \ \ge\ t_{pd,FF} + t_{pd,\text{logic}} + t_{setup}$$
This is the **setup-time constraint**. If violated (the right-hand side exceeds the clock period $T$), $D$ is not guaranteed to have settled by the time the next edge arrives, and the flip-flop may capture a stale, corrupted, or metastable (Topic 08) value. Solving this inequality for the *smallest* valid $T$ (equivalently, the *largest* valid clock frequency $1/T$) is precisely Topic 16's job — this note only establishes the inequality itself, using Topic 13's architecture and Section 1's path-delay machinery.

### 4. The hold-time constraint, and why it does not involve the clock period

Consider the same flip-flop immediately *after* the edge that just captured its value. For that captured value to be reliable, $D$ must not start changing again until at least $t_{hold}$ has elapsed past the edge. The earliest $D$ *could* start changing is bounded by the driving flip-flop's own contamination delay ($t_{cd,FF}$, the earliest its $Q$ might start reflecting the *next* transition) plus the next-state logic's contamination delay (Section 1, the short path through that logic):
$$t_{cd,FF} + t_{cd,\text{logic}} \ \ge\ t_{hold}$$
This is the **hold-time constraint**. Notice, critically, that the clock period $T$ does **not** appear anywhere in this inequality — hold time is a race between the *flip-flop's own edge* and the *fastest possible* path feeding its data input, entirely local to that one edge, with no reference to when the *next* edge occurs. Consequently, a hold-time violation cannot be fixed by slowing down the clock (increasing $T$) the way a setup violation can (Section 3) — if the hold constraint is violated, it is violated at *every* clock speed, including arbitrarily slow ones, because the constraint simply doesn't involve $T$. This asymmetry — setup is a "not enough time before the *next* edge" problem, fixable by a slower clock; hold is a "changed too fast after *this* edge" problem, not fixable by a slower clock at all — is one of the most commonly confused points in real digital design, and is why Section 3 and Section 4 must be checked as two entirely separate conditions.

## Worked examples

### Example 1 — Numeric propagation/contamination delay for a 4-bit ripple-carry adder

Gate delays (assumed, illustrative): 2-input AND, OR, XOR gates each have $t_{pd}=0.2\ \text{ns}$, $t_{cd}=0.1\ \text{ns}$ (a simplification treating all three gate types identically for this example, flagged explicitly since real gates of different types generally differ).

**Propagation delay to $C_4$ (Section 2, $n=4$):** $t_{pd,\text{adder}} = 4\times(0.2+0.2) = 4\times0.4 = 1.6\ \text{ns}$.

**Contamination delay to $C_4$:** $t_{cd,\text{adder}} = 4\times(0.1+0.1) = 4\times0.2=0.8\ \text{ns}$.

**Propagation delay to the final sum bit $S_3$:** the path to $S_3$ only needs $C_{in}^{(3)}$ (from 3 upstream carry stages, not 4) plus one more XOR gate delay (HA2's sum gate, Topic 06 Section 3): $t_{pd}(S_3) = 3\times0.4 + 0.2 = 1.2+0.2=1.4\ \text{ns}$ — shorter than the path to $C_4$, confirming $C_4$ (the overflow bit) is this circuit's true critical-path output, exactly as Topic 06's Self-check Question 7 informally anticipated when it identified the carry-out as the slowest-settling signal for a worst-case input.

### Example 2 — Setup/hold check for Topic 13 Example 2's Moore FSM circuit

Recall Topic 13 Example 2's circuit: $D_1=Q_0\cdot x$ (one AND gate), $D_0=x$ (a direct wire, zero gates). Flip-flop parameters (assumed, illustrative): $t_{pd,FF}=0.3\ \text{ns}$, $t_{cd,FF}=0.15\ \text{ns}$, $t_{setup}=0.15\ \text{ns}$, $t_{hold}=0.1\ \text{ns}$. AND gate: $t_{pd}=0.2\ \text{ns}$, $t_{cd}=0.1\ \text{ns}$ (as in Example 1). The external input $x$ (Topic 13's Core definitions) is not itself the output of any flip-flop in this circuit, so Section 3/4's "driving flip-flop" framing does not literally apply to $D_0=x$'s path in the strict sense — for this worked example, $x$ is assumed, purely for illustration, to arrive from an idealized upstream register sharing this circuit's clock and the same $t_{pd,FF}/t_{cd,FF}$ figures given above; a genuinely asynchronous or independently-clocked external input would need its own, separately-specified arrival-time bound instead, not this circuit's flip-flop parameters.

**Setup check (Section 3), candidate clock period $T=1\ \text{ns}$:** the next-state logic's circuit $t_{pd}$ is the *worse* of the two paths feeding the two flip-flops: $D_1$'s path (one AND gate, $t_{pd}=0.2\ \text{ns}$) versus $D_0$'s path (direct wire, $t_{pd}=0\ \text{ns}$) — the binding (larger) value is $D_1$'s, $t_{pd,\text{logic}}=0.2\ \text{ns}$. Required: $T\ge t_{pd,FF}+t_{pd,\text{logic}}+t_{setup} = 0.3+0.2+0.15=0.65\ \text{ns}$. Since $T=1\ \text{ns} \ge 0.65\ \text{ns}$, the setup constraint is satisfied, with $1-0.65=0.35\ \text{ns}$ of slack.

**Hold check (Section 4):** here the *shorter* path is binding (Section 4's inequality wants the contamination delay to be large *enough*, so the shortest, fastest path is the one at risk of violating it): $D_0$'s direct-wire path has $t_{cd,\text{logic}}=0\ \text{ns}$ (a wire has no delay at all, the fastest possible case). Required: $t_{cd,FF}+t_{cd,\text{logic}} \ge t_{hold}$, i.e. $0.15+0 = 0.15\ \text{ns} \ge 0.1\ \text{ns} = t_{hold}$ — satisfied, with $0.05\ \text{ns}$ of margin. (Checking $D_1$'s AND-gate path too, for completeness: $0.15+0.1=0.25\ \text{ns}\ge0.1\ \text{ns}$, satisfied with even more margin — but it is $D_0$'s zero-delay direct-wire path that is the tightest, binding case for hold, exactly illustrating Section 4's point that hold is governed by the *shortest* path, here literally a bare wire with no gate at all.)

Both constraints are satisfied for this circuit at $T=1\ \text{ns}$ — a fully verified, working synchronous design at this clock period, using the exact same next-state equations Topic 12 and Topic 13 derived under the zero-delay idealization, now confirmed to also work under a real, nonzero-delay timing model.

## Common pitfalls

- **Using $t_{pd}$ where $t_{cd}$ belongs, or vice versa, in a setup/hold check.** Setup (Section 3) is a worst-case ("did the signal have *enough* time") condition and uses $t_{pd}$ throughout; hold (Section 4) is a best-case ("did the signal change *too soon*") condition and uses $t_{cd}$ throughout. Swapping them produces a check that looks rigorous but verifies the wrong thing entirely — e.g. using $t_{cd}$ (an optimistic, best-case number) in a setup check could pass a circuit that will actually fail in the real (worst-case) world.
- **Believing a hold violation can be fixed by slowing down the clock.** Section 4 derived the hold constraint with *no* $T$ term at all — a hold violation is a fixed property of the flip-flop's and logic's delays, present at every clock speed; only changing the delays themselves (faster flip-flop clock-to-$Q$, or deliberately *added* delay on a too-fast short path) can fix it. This is one of the most common real-world confusions this note exists to prevent.
- **Treating the uncertain window $(t_{cd},t_{pd})$ (Core definitions) as a signal value the circuit actually produces.** It is a statement about the limits of a timing *model's* guarantees (what can and cannot be promised about when a transition happens), not a third electrical state a wire sits in — directly analogous to (but not to be confused with) 6.002 Topic 04's forbidden voltage band, which is a genuinely different, voltage-axis concept.
- **Forgetting the flip-flop's own $t_{pd,FF}/t_{cd,FF}$ contributes to the timing budget, and only counting combinational gate delays.** Both Section 3's setup inequality and Section 4's hold inequality explicitly include the flip-flop's clock-to-$Q$ delay as a term — a design that only accounts for gate delays in the next-state logic while ignoring the sourcing flip-flop's own delay will underestimate the true worst-case (or overestimate the true best-case) timing.
- **Assuming Topics 03–13's zero-delay proofs are now "wrong" or need to be redone.** Those proofs established *logical* correctness — that the right value is eventually computed/captured, given enough time — which remains true and necessary; this note adds an *additional*, independent layer of *timing* correctness (that the right value arrives *in time* for the next edge) on top of, not instead of, the earlier logical guarantees. A circuit needs both to actually work.
- **Assuming the critical path (Section 1) is always the path with the most gates.** A path with fewer, slower gates can have a larger $t_{pd,\text{path}}$ than a path with more, faster gates — critical-path analysis is about summed delay values, not raw gate (or hop) count; Example 1's comparison between the $C_4$ path (4 stages) and the $S_3$ path (3 stages plus one extra gate) already shows path length in "stages" isn't quite the same as path length in gates, and neither is automatically the same as total delay without actually summing the specific gate delays involved.

Would the per-stage delay necessarily be smaller, larger, or is it impossible to say without more information?

### Answers

1. Propagation delay ($t_{pd}$): the worst-case (maximum) time from an input change to the gate's output being guaranteed to have reached its final correct value. Contamination delay ($t_{cd}$): the best-case (minimum) time from an input change to the earliest point the output might start to change.
2. False. Per Section 4, the hold-time constraint ($t_{cd,FF}+t_{cd,\text{logic}}\ge t_{hold}$) contains no clock-period term at all — it is a fixed property of the flip-flop's and logic's own delays, violated (or not) at every clock speed equally; only changing those delays (not the clock period) can fix a hold violation.
3. $t_{pd,\text{path}} = 0.15+0.25=0.40\ \text{ns}$ (Section 1, sum of $t_{pd}$'s). $t_{cd,\text{path}}=0.05+0.1=0.15\ \text{ns}$ (sum of $t_{cd}$'s).
4. Per Section 2's per-stage formula, the path to $C_2$ passes through only 2 carry stages (bit 0's and bit 1's), not 4: $t_{pd}(\text{to }C_2) = 2\times(0.2+0.2)=0.8\ \text{ns}$ — smaller than the $1.6\ \text{ns}$ delay to $C_4$ because $C_2$ only needs the carry to ripple through 2 stages of the chain, not all 4; it's an earlier (lower-index) output in the ripple sequence, needing less carry propagation to become valid.
5. Setup requires $T \ge t_{pd,FF}+t_{pd,\text{logic}}+t_{setup}$. Here $t_{pd,\text{logic}}=0$ (direct wire, no combinational logic in between). Required: $T\ge 0.4+0+0.1=0.5\ \text{ns}$. Given $T=0.5\ \text{ns}$ exactly matches the required minimum — the constraint is satisfied, but with *zero* slack (a marginal, exact-boundary case; in real design practice this offers no safety margin for any modeling imprecision, echoing 6.002 Topic 04's caution about zero-margin designs).
6. (a) Setup requires $T\ge t_{pd,FF}+t_{pd,\text{path}}+t_{setup}$ for *each* path, and the clock period must satisfy the tightest (largest) of these simultaneously. Path 1: $T\ge0.2+0.9+0.15=1.25\ \text{ns}$. Path 2: $T\ge0.2+0.3+0.15=0.65\ \text{ns}$. The binding (larger) requirement is Path 1's: minimum valid $T=1.25\ \text{ns}$. (b) Hold requires $t_{cd,FF}+t_{cd,\text{path}}\ge t_{hold}=0.2\ \text{ns}$ for each path, independent of $T$. Path 1: $0.1+0.7=0.8\ge0.2$ — satisfied, with large margin. Path 2: $0.1+0.05=0.15 < 0.2$ — **violated**, and since this inequality has no $T$ term, it is violated at *every* clock period, including the $T=1.25\ \text{ns}$ found in part (a); Path 2 is the binding (and here, failing) constraint for hold, while Path 1 was the binding constraint for setup — illustrating that the two checks can have *different* binding paths (the slowest path matters for setup, the fastest for hold), and that a circuit can pass one check while failing the other regardless of clock speed.
7. It is impossible to say for certain without the specific $t_{pd}$ value of a 3-input complex gate realizing $AB+BC_{in}+AC_{in}$ directly — but the qualitative reasoning is: the AND-then-OR (two-half-adder) decomposition has *two* gate delays in series on the carry-critical path ($t_{pd,AND}+t_{pd,OR}$), whereas a single complex gate computing the same Boolean function in one gate-level step would have only *one* gate's delay on that path — generally, collapsing multiple series gates into a single complex gate (Topic 04) tends to reduce the number of delays that must be *summed* in series, which often (though not automatically, since a complex gate's own single $t_{pd}$ could in principle be larger than the sum of two simpler gates', depending on the specific electrical implementation) reduces the overall per-stage delay compared to a multi-gate decomposition — the correct, certain answer requires the actual specified $t_{pd}$ of that specific complex gate, which is exactly why this note treats gate delay as a given parameter (Topics 03–04's realization choice) rather than something derivable from the Boolean function alone.
8. Section 3's setup constraint involves $t_{pd}$ values (worst-case, and does involve $T$) while Section 4's hold constraint involves $t_{cd}$ values (best-case, and does *not* involve $T$) — the two inequalities share no common terms that would force one to imply the other. A circuit could have a comfortably large $t_{pd,\text{logic}}$ margin relative to a generous clock period $T$ (satisfying setup easily) while *also* having an uncomfortably small $t_{cd,\text{logic}}$ on some other, faster path (violating hold) — Self-check Question 6 is a direct concrete instance of exactly this scenario (Path 1 satisfies setup easily and is irrelevant to the hold failure; Path 2 satisfies setup easily too, yet independently violates hold). Since $t_{pd}$ and $t_{cd}$ are, in general, unrelated numbers describing different (worst-case vs. best-case) physical extremes of the same gates, satisfying one inequality provides no logical information about the other.

## Summary / cheat sheet

**Gate delay:** $t_{pd}$ (worst-case, output guaranteed done) and $t_{cd}$ (best-case, output guaranteed not yet started), $t_{cd}\le t_{pd}$.

**Path/circuit delay (Section 1):** path delay $=$ sum of gate delays along that path; circuit $t_{pd}=\max$ over paths (critical path); circuit $t_{cd}=\min$ over paths (short path).

**Ripple-carry adder (Section 2):** $t_{pd}(\text{to }C_n) = n\cdot(t_{pd,AND}+t_{pd,OR})$ — grows linearly in $n$, quantifying Topic 06's informal flag.

**Setup constraint (Section 3):** $T \ge t_{pd,FF}+t_{pd,\text{logic}}+t_{setup}$ — a worst-case, $T$-dependent condition; violations fixable by slowing the clock.

**Hold constraint (Section 4):** $t_{cd,FF}+t_{cd,\text{logic}} \ge t_{hold}$ — a best-case condition with **no** $T$ dependence; violations are present at every clock speed and must be fixed by changing delays, not the clock.
